Especificación de la Arquitectura del Sistema

Análisis del patrón de diseño implementado en este Taller Práctico

Este software está construido sobre el framework corporativo Django, utilizando el patrón arquitectónico estructural MVT (Model-View-Template). A diferencia del MVC convencional, Django gestiona de forma nativa el acoplamiento de sus componentes para acelerar el despliegue:

Capa de Modelos (Model)

Gestiona la persistencia de datos. Mediante el uso del **ORM integrado de Django**, las clases de Python se mapean y traducen automáticamente a tablas relacionales dentro del motor local **SQLite3 (db.sqlite3)**, evitando la necesidad de inyectar sentencias SQL puras manuales.

Capa de Vistas (View)

Representa el cerebro y la lógica de negocio del backend. Ubicado en el archivo views.py, se encarga de interceptar las peticiones HTTP (requests) enviadas por el cliente, procesar los datos requeridos y retornar un objeto de respuesta compilado hacia el navegador de la Mac.

Capa de Plantillas (Template)

Es la capa de presentación semántica (interfaz del usuario). Utiliza el motor Django Template Language (DTL) para permitir el renderizado dinámico de datos y la inclusión segura de recursos estáticos mediante etiquetas de servidor como {% load static %}.

Ciclo de Vida de una Petición HTTP en este Proyecto

  1. El cliente ingresa a la dirección local del servidor o dominio web desde su máquina.
  2. El archivo central de enrutamiento urls.py intercepta la petición, analiza la cadena de texto y delega el control a la función correspondiente.
  3. La función index en el controlador views.py procesa la lógica y extrae el diccionario de contexto corporativo.
  4. El motor de plantillas unifica el archivo index.html con las hojas de estilos estilos.css y genera código plano interpretable por el cliente.

Protocolos de Seguridad & Control de Versiones

Auditoría del entorno virtual y exclusión de dependencias críticas

El Rol Estratégico del Archivo .gitignore

Durante la inicialización de este repositorio Git conectado a GitHub, se implementó una directiva estricta de aislamiento de archivos en la raíz del proyecto para cumplir con los estándares internacionales de desarrollo de software:

Archivo / Carpeta Excluida Razón Técnica de la Exclusión (Seguridad y Rendimiento)
env/ o venv/ El entorno virtual contiene binarios y dependencias compiladas exclusivas para el sistema operativo de desarrollo (macOS). Su inclusión en GitHub corrompería el despliegue en sistemas Windows o Linux y agregaría más de 40 MB de basura al repositorio.
db.sqlite3 Aísla la base de datos de pruebas local. Evita la exposición involuntaria de registros de usuarios, configuraciones del sistema o datos confidenciales de desarrollo en servidores públicos de internet.
__pycache__/ y *.pyc Excluye los archivos de bytecode compilados generados automáticamente por el intérprete de Python, manteniendo el historial de commits limpio y enfocado puramente en código fuente editable.
